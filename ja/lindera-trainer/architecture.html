Lindera ドキュメント

アーキテクチャ

モジュール構成

lindera-trainer/src/
├── lib.rs                # Trainer: CRF学習の実行制御。パブリックAPIの再エクスポート
├── config.rs             # TrainerConfig: 種辞書・char.def・unk.def・feature.def・rewrite.defのパース
├── corpus.rs              # Corpus, Example, Word: 学習データの表現
├── feature_extractor.rs  # FeatureExtractor: 素性テンプレート解析と素性ID管理
├── feature_rewriter.rs   # DictionaryRewriter: MeCab互換の3セクション書き換え
└── model.rs               # Model, SerializableModel: 学習済みモデルの保持・シリアライズ・辞書出力

主要コンポーネント

TrainerConfig

学習に必要な5つの入力ファイル――種辞書（lex.csv）、文字定義（char.def）、未知語定義（unk.def）、素性テンプレート（feature.def）、書き換えルール（rewrite.def）――をパースし、Trainerが利用する設定情報にまとめます。TrainerConfig::from_readers（またはファイルパスを直接渡せるラッパーのfrom_paths）は、種辞書から表層形と素性の語彙を抽出し、パースした素性テンプレートからFeatureExtractorを構築し、書き換えルールからDictionaryRewriterを構築し、さらに種辞書・文字定義・未知語定義をもとにインメモリのlindera_dictionary::dictionary::Dictionaryを組み立てます。char.defは辞書ビルダー（CharacterDefinitionBuilder::build_from_str）でパースするため、学習時の文字カテゴリはビルドされる辞書と同じになります。%t素性に使う各文字の既定カテゴリは、ビルダーのbuild_default_category_tableから得ます。このDictionary（dict()）は学習用ラティスの材料を持ちます。prefix_dictionary（system_lexicon()）は種辞書で、種辞書の表層形を収めたprefix dictionaryの単語IDは行番号です。unknown_dictionary（unk_handler()）は、辞書ビルダーのparse_unkで読んだunk.defのエントリを、ファイル順に1行1エントリで持ちます。これらのコストと文脈IDは学習では使わず、Dictionaryの連接行列はプレースホルダーです。TrainerConfigは、種辞書の素性文字列と、unk.defのエントリを(カテゴリ, 素性文字列)の組としてファイル順にも保持し、ラベルとエクスポートするunk.defはこれらから作ります。unk.defでは、#で始まる行と空行を読み飛ばし、フィールドが5つ未満の行と、文脈IDやコストが数値でない行は、その行を示すエラーになります。from_readersは、mecab-dict-indexやlindera buildと同じく、それより前の行で定義していないカテゴリを指すchar.defの範囲行、2回定義したカテゴリ、char.defにないカテゴリを指すunk.defの行、unk.defの行がないchar.defのカテゴリも拒否します（lindera_dictionary::dictionary::unknown_dictionary::check_unknown_word_categories）。そのため、こうした入力は、エクスポートしたファイルのビルドではなく、学習の前に失敗します。また、surfaces()、surface_features()、get_features()に加え、user_lexicon() / add_user_lexicon_entry() / load_user_lexicon_from_content()によるユーザー辞書へのアクセス、metadata()も提供します。

Corpus / Example / Word

アノテーション付き学習データを表現します。Wordは表層形とその素性文字列（カンマ区切り）のペアです。Exampleは1つの学習用の文であり、Vec<Word>から構築され、各語の表層形を連結して元の文を復元します。CorpusはExampleの集合です。Corpus::from_readerはタブ区切りのsurface<TAB>features形式の行をパースし、空行またはEOSのみの行を文の区切りとして扱います。

FeatureExtractor

MeCab互換の素性テンプレートを解析し、生成された素性文字列から内部で採番されるNonZeroU32型の素性IDへのマッピングを管理します。サポートされるテンプレートのプレースホルダは、%F[n] / %F?[n]（インデックスnの素性フィールド。?付きは値が*の場合にスキップ）、%t（文字カテゴリ）、%w（表層形、ユニグラムのみ）、%u / %l / %r（書き換え後のユニグラム／左文脈／右文脈の素性文字列全体）、およびバイグラムの左右文脈フィールド用の%L[n] / %L?[n] / %R[n] / %R?[n]です。%F[n]・%L[n]・%R[n]が最後の列より後ろを読むテンプレートは、?の有無にかかわらず、MeCabの学習器と同じく素性を作りません。extract_unigram_feature_ids[_with_ctx]、extract_left_feature_ids[_with_ctx]、extract_right_feature_ids[_with_ctx]は、パース済みテンプレートを素性の配列（バイグラム抽出の場合は表層形／ufeature／lfeature／rfeatureを保持するオプションのTemplateContextも併せて）に適用し、対応する素性IDを返します。初回利用時には新しいIDが割り当てられます。

DictionaryRewriter

MeCabの3セクション形式rewrite.def（[unigram rewrite]、[left rewrite]、[right rewrite]）を実装します。各セクションはpattern<TAB>replacement形式のルールの並びを持ち、内部のFeatureRewriterBuilderによってFeatureRewriterというprefix trie（前方一致木）に構築されます。DictionaryRewriter::from_readerは3セクションすべてをパースしますが、セクションヘッダのないファイルは後方互換性のため（右文脈書き換えのみのレガシー形式として）扱います。rewrite()は素性文字列に3つの書き換え器すべてを適用し、(ufeature, lfeature, rfeature)を返します。マッチするルールがないセクションは入力をそのまま通過させます。MeCabと同じく、素性と各ルールのパターン・置換はMeCabのtokenizeCSVの規則（クレート内部のfeature_csv::split_feature）で列に分けるので、,を含む引用付きの列は1つの列です。rewrite()は書き換えた列を,でつなぎ、,か"を含む列は引用符で囲みます。学習器は、素性テンプレートのために3つの結果を同じく列に分けます。（かつてのrewrite_cached()は素性文字列全体をキーにメモ化していましたが、実辞書の素性は行ごとにほぼ一意でキャッシュが一度もヒットしないため削除されました — #975。）

Trainer

Trainer::newはCRFのラベルを作ります。まず種辞書の行ごとに行順で1つ（ラベル行番号 + 1。単語IDが行番号である学習用辞書での一致を、そのままラベルに対応付けるため）、続いてunk.defのエントリごとにファイル順で1つ作り、その%tはエントリのカテゴリのIDです。Trainer::trainは、MeCabの学習器と同じく、例文ごとにlindera_crf::Latticeを1つ作ります。

  • 各位置の候補は、その位置から始まる種辞書の語と、ランタイムがその位置に作る未知語です。未知語はlindera_dictionary::viterbi::Lattice::unknown_word_candidatesが列挙します。文字の既定カテゴリの未知語を、そのINVOKE・GROUP・LENGTHの設定で、カテゴリのunk.defのエントリそれぞれについて作ります。
  • 正解の各トークンには、範囲と素性文字列全体が同じ最初の種辞書の行のラベルを付けます。なければ、範囲が同じ未知語候補のunk.defエントリのうち、*以外の素性の列がすべて正解トークンの列と一致するファイル順で最初のエントリのラベルを付けます（どちらの列もrewrite()と同じく分けます）。それもなければ、MeCabの学習器が仮想ノードを追加するのと同じく、正解の素性文字列から作る仮想ラベル（%tは0、%wなし、素性文字列ごとに1つ）を付けます。仮想ラベルはほかのラベルの後に並び、学習されますが、エクスポートされることはありません。
  • それ以外の候補はすべて負例の辺になります。

ラティスを作り終えると、Lattice statistics:の行を出力します。各方法でラベルを付けた正解トークンの数（gold_lexicon・gold_unknown・gold_virtual）、仮想ラベルの数（virtual_labels）、種辞書と未知語候補それぞれから作った負例の辺の数（negative_lexicon・negative_unknown）です。正解トークンがあり、種辞書の語であるものが1つもないとき、または表層を持つ種辞書の行はあるものの素性文字列が一致する行がない正解トークンが種辞書の語より多いときは、続けて標準エラーに警告を書きます。バインディングはlogクレートのロガーを設定しないので、logクレートではなくeprintln!で書きます。警告には、そうした最初の正解トークンと、その表層を持つ種辞書の行のうち最初の5行の素性文字列が並びます。Trainer::max_grouping_lenは、ランタイムと同じ意味（先頭の1文字を除いた文字数。デフォルトのNoneは無制限）で未知語のグルーピングの長さに上限を設けます。ほかのビルダーメソッドは、正則化（デフォルトはL2とDEFAULT_LAMBDAの1.0。use_l2(false)でL1）・イテレーション数の上限・収束判定の許容値（Trainer::eta。デフォルトはDEFAULT_ETAの5e-5。lindera-crfのアーキテクチャを参照）・スレッド数を設定します。学習の後に、最適化が止まった理由を、イテレーション数と損失・勾配の評価回数とともに出力します。あるイテレーションで目的関数が変わらなかったときと、ライン探索が失敗したときは、続けて標準エラーに警告を書きます。種辞書の語の警告と同じくeprintln!で書きます。

Model / SerializableModel

ModelはTrainer::trainが生成する学習済みモデルです。学習されたlindera_crf::RawModel、学習に用いたTrainerConfig、抽出済みの素性の重みとラベル、仮想ラベルの素性文字列、そして学習後にread_user_lexiconで追加されたユーザー辞書エントリを保持します。学習されたCRFの重みは、MeCab互換の整数コストに変換されます（tocost(weight, cost_factor) = clamp(round(-weight * cost_factor), i16::MIN, i16::MAX)、すなわち[-32768, 32767]の範囲にクランプされます）。この際のコストファクターは、i16の値域を最大限活用できるよう計算されます（calculate_cost_factor）。Modelは自身をシリアライズでき（write_model）、辞書ソースファイルを直接エクスポートすることもできます。

SerializableModelは、Model::read_modelがリーダーから以前学習したモデルを読み込んだ際に返される、rkyvでシリアライズ可能な素のデータ型です（lindera export CLIコマンドで使用されます）。Modelと同じ学習結果の情報――素性の重み、ラベル、品詞情報、連接コスト行列、unk.defのエントリ（unk_entries。ファイル順の(カテゴリ, 素性文字列)の組）、保存されているchar.def / feature.def / rewrite.defの内容、コストファクター、左右文脈IDマッピング――をTrainerConfigを持たない所有データとして保持し、辞書エクスポートファイルを生成するための独自のライターメソッド群を提供します。

Modelのパブリックメソッド

メソッド説明
read_user_lexicon<R: Read>(&mut self, rdr: R) -> Result<()>ユーザー定義辞書（種辞書と同じsurface,left_id,right_id,cost,feature...のCSV形式）をモデルに読み込みます。これにより、エントリが与えていないパラメータをwrite_dictionaryが埋められるようになります。MeCabのmecab-dict-indexと同じく、コストと連接IDは別々に埋めます。空のコストは計算し、連接IDのどちらかが空か負の数なら、両方を推定します。パラメータが0,0,0のエントリは、Vibratoの学習器と同じく3つとも埋めます（mecab-dict-indexはそのまま使います）。空でも範囲内の数でもない連接IDやコストは、そのエントリを示すエラーになり、そのときはエントリを1つも追加しません。mecab-dict-indexはそうした値をatoiで数として読みますが、lindera buildは拒否します。ユーザー辞書が必要な場合は、辞書を書き出す前に呼び出す必要があります。
write_model<W: Write>(&self, writer: &mut W) -> Result<()>学習済みモデル全体（素性の重み、ラベル、品詞情報、連接行列、unk.defのエントリ、保存された定義ファイルの内容、コストファクター、左右IDマッピング）をrkyvバイナリ形式でシリアライズします。metadata.versionはmodel::MODEL_FORMAT_VERSION（3.0.0）です。保存する行列の大きさは、重みが残ったかどうかにかかわらず、モデルのすべての文脈IDを覆います。出力はバイト単位で再現可能です。連接行列は順序付きマップ、unk.defのエントリはVecであるため、バイト列はモデルの内容だけで決まります。
read_model<R: Read>(reader: R) -> Result<SerializableModel>関連関数。write_modelが書き出したデータからSerializableModelをデシリアライズします。まずrkyv形式を試み、ペイロードが実際にJSONオブジェクトで始まる場合にのみレガシーのJSON形式へフォールバックします。いずれでもない場合は、形式の不一致として再学習を促すエラーを返します。どちらの形式でも、metadata.versionがMODEL_FORMAT_VERSIONでないモデルは同じエラーで拒否するため、7.0.0より前に書かれたモデルはすべて再学習が必要です。feature_setsフィールドが存在しない旧形式のモデルについては、feature_weightsから補完します。
write_dictionary<W1, W2, W3, W4>(&self, lexicon_wtr, connector_wtr, unk_handler_wtr, user_lexicon_wtr) -> Result<()>レキシコン、連接コスト行列、未知語辞書、ユーザー辞書を一度にまとめて書き出す便利メソッドです。ユーザー辞書はread_user_lexiconで読み込んだエントリを入力順で書き出します。連接IDのないエントリには、素性がそのエントリに最も近い種辞書の行にlex.csvが付ける連接IDを割り当てます。コストのないエントリには、MeCabのcalcCostと同じく、そのエントリのunigram素性の学習済みの重みの和を、lex.csvのコストファクターでtocostにより変換したコストを割り当てます。素性は種辞書の行と同じく、書き換えた素性、先頭の文字の既定カテゴリ（%t）、表層形（%w。MeCabはunigramテンプレートの%wを受け付けません）から作ります。そのため、素性と先頭の文字のカテゴリが種辞書のある行と同じエントリは、lex.csvがその行に付けるコストを受け取ります。モデルに重みのない素性は何も足しません。エントリが与えたパラメータはそのまま書き出します。最も近い行は、エントリと同じ位置で一致する列ごとに、前の列ほど高い点を足した合計が最も高い行で、同点なら最初の行です。どの種辞書の行とも共通の列を持たない素性の、連接IDのないエントリは、MeCabのmecab-dict-indexと同じくエラーになり、そのときは何も書き出しません。
write_lexicon<W: Write>(&self, writer: &mut W) -> Result<()>マージされたCRFモデルから得た連接IDとコストを用いて、種辞書の各語彙エントリについてlex.csv形式のエントリ（surface,left_id,right_id,cost,features...）を書き出します。
write_connection_costs<W: Write>(&self, writer: &mut W) -> Result<()>マージしたモデルの文脈IDのすべての(right_id, left_id)の組み合わせ（BOS/EOS用の0を含む）を網羅する密なmatrix.def形式の連接コスト行列を書き出します。各組み合わせのコストは、学習した重みをtocostで変換したものです。学習した重みがない組み合わせ（バイグラム素性が学習中に隣り合わなかったか、正則化で重みが0になったもの）は0になります。これは学習中のその遷移のコストであり、MeCabのmecab-dict-genが書き出す値でもあります。write_modelが書き出すモデルについてSerializableModel::write_connection_costsが書き出す行列と同じです。
write_unknown_dictionary<W: Write>(&self, writer: &mut W) -> Result<()>学習に使ったunk.defのエントリごとに、ファイル順でunk.defの行を1行ずつ書き出します。各行は、エントリのカテゴリ名と素性文字列、学習された連接IDとコストを持ちます。
get_unknown_word_cost(&self, category: usize) -> i32char.defのカテゴリのインデックスに対する入力のコストを返します。学習した値ではなくunk.defのコスト列の値で、エントリが複数あるカテゴリでは最後の行のコストです。設定がない場合はデフォルト値2000を返します。
num_features(&self) -> usize学習済みモデルが保持する素性の重みの数を返します。
num_labels(&self) -> usize学習済みモデルのエクスポートされるラベル（種辞書の行とunk.defのエントリの合計）の数を返します。仮想ラベルは数えません。
raw_model(&self) -> &lindera_crf::RawModel高度な操作や低レベルの処理のために、内部のlindera-crfのraw modelへアクセスします。

SerializableModelのパブリックメソッド

Model::read_modelが返す値に対して利用できるメソッド群で、以前に学習・シリアライズされたモデルから辞書ソースファイルを再エクスポートするために使用します（lindera export CLIコマンドと、Python・Node.js・Ruby・PHPバインディングのエクスポート関数で利用されます）。

メソッド説明
export(&self, output_dir: &Path, base_metadata: Option<&Path>) -> Result<Vec<PathBuf>>以下のメソッドで、辞書ソースファイルをoutput_dirに書き出します（output_dirがなければ作成します）: lex.csv、matrix.def、unk.def、char.def、feature.def、rewrite.def、left-id.def、right-id.defと、base_metadataを指定したときはmetadata.json（update_metadata_json）です。書き出したファイルのパスをこの順序で返します。lindera exportとバインディングのエクスポート関数はこのメソッドを呼ぶため、同じファイルを書き出します。metadata.jsonを最初に作るため、ベースのmetadata.jsonを読めないときはファイルを1つも書き出さずに失敗します。エラーはファイルを示します。
write_lexicon<W: Write>(&self, writer: &mut W) -> Result<()>保存されているfeature_sets、labels、pos_infoから、種辞書の行の後に続くunk.defのエントリのラベルを除いてlex.csv形式のエントリを書き出します。
write_connection_costs<W: Write>(&self, writer: &mut W) -> Result<()>保存されているconnection_matrix、max_left_id、max_right_idから、密なmatrix.def形式の連接コスト行列を書き出します。大きさはmax_right_id + 1行×max_left_id + 1列で、学習でバイグラムの重みが1つも残らなかった場合もモデルのすべての文脈IDを覆います。connection_matrixにないセル（学習した重みがない連接）は、Model::write_connection_costsと同じく0になります。
write_unknown_dictionary<W: Write>(&self, writer: &mut W) -> Result<()>保存されているunk_entriesのエントリごとに、ファイル順でunk.defの行を1行ずつ書き出します。各行は、カテゴリ名、学習された連接IDとコスト、素性文字列を持ちます。
write_char_def<W: Write>(&self, writer: &mut W) -> Result<()>元の学習入力からそのまま保存されているchar.defの内容を書き出します。
write_feature_def<W: Write>(&self, writer: &mut W) -> Result<()>元の学習入力からそのまま保存されているfeature.defの内容を書き出します。
write_rewrite_def<W: Write>(&self, writer: &mut W) -> Result<()>元の学習入力からそのまま保存されているrewrite.defの内容を書き出します。
write_left_id_def<W: Write>(&self, writer: &mut W) -> Result<()>保存されているleft_id_mapからleft-id.defを書き出します。先頭行は0 BOS/EOSです。
write_right_id_def<W: Write>(&self, writer: &mut W) -> Result<()>保存されているright_id_mapからright-id.defを書き出します。先頭行は0 BOS/EOSです。
update_metadata_json<W: Write>(&self, base_metadata_path: &Path, writer: &mut W) -> Result<()>ベースとなるmetadata.jsonを読み込み、学習結果に基づく値（素性の重みの中央値から推定したdefault_word_cost、および素性・ラベル数や文脈IDの範囲・connection_matrix_sizeとしてのmatrix.defの大きさ（{行数}x{列数}）・学習メタデータを含むmodel_infoセクション）で更新した結果を書き出します。タイムスタンプは含まれず、同じモデルに対してバイト単位で再現可能です。

ModelMetadataとFeatureSetInfo

ModelMetadataは学習実行に関する要約情報を保持します: version（モデルの形式バージョンMODEL_FORMAT_VERSION）、regularization（使用した正則化コスト係数）、regularization_type（使用したRegularizationType。model_info.regularization_typeとしてエクスポートされます）、elastic_net_l1_ratio（L1 の比率。種類が Elastic Net のときだけ値を持ち、そのときだけエクスポートされます）、iterations（実際に回ったL-BFGSのイテレーション数。Trainer::max_iterで設定した最大値以下。model_info.training_iterationsとしてエクスポートされます）、feature_count、label_countです。SerializableModel::metadataに格納されます。

FeatureSetInfoは、学習後にマージされたCRFモデルから抽出された、ラベルごとの連接情報を保持します: left_id、right_id、weightです。SerializableModel::feature_setsには、CRFのラベルごとに1エントリが格納されます。labelsの各要素に対応するエントリが同じ順序で並び、その後にエクスポートされない仮想ラベルのエントリが続きます。

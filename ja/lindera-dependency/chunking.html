Lindera ドキュメント

文節の区切り

文節の区切り（チャンキング）は、文の形態素を文節にまとめます。形態素ごとに、文節を始める（B）か、続ける（I）かを決めます。CaboCha と同じく、この 2 つのラベルの条件付き確率場を使います。

区切りは既定のビルドに入っていて、ほかのクレートを必要としません。モデルは、素性の文字列から B と I の重みへの表と、遷移の重みで、ラベルは Viterbi で求めます。表は、モデルファイルの中の位置のまま読みます。学習は train feature の裏にあります。

文を区切る

#![allow(unused)]
fn main() {
use lindera_dependency::lattice::{self, LatticeMorpheme};
use lindera_dependency::model::Model;
use lindera_dependency::{Bunsetsu, Morpheme, Sentence};

let model = Model::new(std::fs::read("chunker.model")?)?;
let chunker = model.chunker().expect("the file has a chunker");

// The morphemes of 彼は本を読んだ。 as IPADIC gives them. Any type that
// implements `Morpheme` will do.
let morphemes = vec![
    LatticeMorpheme::new("彼", "名詞,代名詞,一般,*,*,*,彼,カレ,カレ"),
    LatticeMorpheme::new("は", "助詞,係助詞,*,*,*,*,は,ハ,ワ"),
    LatticeMorpheme::new("本", "名詞,一般,*,*,*,*,本,ホン,ホン"),
    LatticeMorpheme::new("を", "助詞,格助詞,一般,*,*,*,を,ヲ,ヲ"),
    LatticeMorpheme::new("読ん", "動詞,自立,*,*,五段・マ行,連用タ接続,読む,ヨン,ヨン"),
    LatticeMorpheme::new("だ", "助動詞,*,*,*,特殊・タ,基本形,だ,ダ,ダ"),
    LatticeMorpheme::new("。", "記号,句点,*,*,*,*,。,。,。"),
];

// The ranges of the bunsetsu, as indices into the morphemes.
let ranges = chunker.chunk(&morphemes)?;
assert_eq!(ranges, [0..2, 2..4, 4..7]);
}

Chunker::chunk は &self を取り、chunker は Send + Sync なので、1 つの chunker を複数のスレッドで使えます。先頭の形態素は必ず文節を始め、空の文には文節がありません。

形態素は、モデルを学習した辞書のもので、同じ設定で分かち書きしたものでなければなりません。モデルは 1 つの辞書に属します。モデルのスキーマが読む列より少ない列しか持たない形態素は、エラーで断ります。辞書の照合を参照してください。

主辞と機能語を付ける

モデルファイルは、辞書のスキーマを持っていて、そこから各文節の主辞と機能語が決まります。次の例は、結果をラティス形式で書き出します。ここでの係り先は仮のもので、どの文節も次の文節に係るとしています。係り先は解析器が求めます。

#![allow(unused)]
fn main() {
let schema = model.schema();
let count = ranges.len();
let bunsetsu = ranges
    .into_iter()
    .enumerate()
    .map(|(index, range)| {
        let positions = schema.positions(&morphemes[range.clone()]);
        let mut bunsetsu = Bunsetsu::new(range, (index + 1 < count).then_some(index + 1));
        bunsetsu.positions = positions;
        bunsetsu
    })
    .collect();
let sentence = Sentence::new(morphemes, bunsetsu)?;
let mut output = Vec::new();
lattice::write(&mut output, &sentence)?;
print!("{}", String::from_utf8(output)?);
}

モデルを学習する

Lindera が公開する IPADIC のモデルには、区切りが入っています。UniDic のモデルも同じです。自分のモデルは、学習データから学習します。

cargo run --release -p lindera-cli -- dependency train-chunker \
    --input train.lattice --output chunker.model

モデルは IPADIC のものになります。--dictionary-name でほかの辞書（unidic・unidic-cwj・unidic-csj）を指定すると、その辞書の名前とスキーマがモデルに入り、列・テンプレート・係数はその辞書の設定になります。

IPADIC で変換した UD Japanese-GSD の train では、数秒で終わり、最後に次を出力します。

train.lattice: 7024 sentences
iterations: 126
feature strings: 4325
weights: 8656
bytes: 261857

出力は、辞書 ipadic のモデルファイルで、部分は区切りだけです。同じデータで学習し直すと、同じバイト列になります。重みは f64 です。形式は、最初のリリースまでに変わることがあります。

オプション既定意味
--regularizationl1l1 か l2
--lambda0.5正則化の係数
--columnssurface,pos,cformテンプレートが読む列。surface（表層）、pos（品詞の階層を - でつないだもの）、ctype（活用型）、cform（活用形）、base（原形）
--templateCaboCha の区切りのテンプレートに、3 列目の 5 行を足したものCRF++ の形式のファイル
--max-iterations1000反復の上限
--threadsCPU の数スレッドの数

chunk は、モデルでファイルの形態素を区切り直します。evaluate で正解と比べるためのものです。

cargo run --release -p lindera-cli -- dependency chunk \
    --model chunker.model --input dev.lattice --output output.lattice

どの文節も次の文節に係るとして書き出します。区切りだけを測るためです。区切ってから解析するのは parse --input-layer morphemes です。

UniDic の場合

train-chunker --dictionary-name unidic（または unidic-cwj・unidic-csj）は、IPADIC とは別の設定で学習します。列は、表層・品詞・活用形・原形の 4 つで、テンプレートは Template::unidic()、正則化は L1 の係数 0.25 です。辞書の設定は TrainOptions::for_dictionary が返します。IPADIC の場合と同じく、コマンドのオプションで、どれも置き換えられます。

設定は、train の交差検証で UniDic CWJ を使って選び直しました。残りの 2 つの辞書でも同じ結論です。UniDic の原形は語彙素で、表記が違っても同じ値になります。IPADIC では効かなかった原形が、ここでは効きます。10 分割の F、片方の設定だけが正しく区切った文の数、McNemar の検定の結果です。

素性の作り方

素性の文字列は 2 段階で作り、どちらも差し替えられます。

  1. 列。 形態素ごとに、モデルの列をスキーマを通して読みます。表層、品詞、活用形です。
  2. テンプレート。 CRF++ の形式のテンプレートが、その形態素と前後の形態素の列を、素性の文字列に展開します。U02:%x[0,0] はその形態素の 1 列目、U11:%x[-1,1] は 1 つ前の形態素の 2 列目です。文の外の位置は _B-1、_B+1 などになります。

復号は、素性の文字列と重みの表だけを見ます。Chunker::features が文字列を作り、Chunker::labels がそれを復号するので、自分で書いた取り出し方から同じ復号を使えます。

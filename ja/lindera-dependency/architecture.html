主要コンポーネント

Morpheme

形態素は、表層と、辞書の素性の列です。Morpheme は trait なので、このクレートはトークナイザに依存せず、自分で定義した型も解析できます。

#![allow(unused)]
fn main() {
use lindera_dependency::Morpheme;

struct Word {
    surface: &'static str,
    features: [&'static str; 2],
}

impl Morpheme for Word {
    fn surface(&self) -> &str {
        self.surface
    }

    fn feature(&self, index: usize) -> Option<&str> {
        self.features.get(index).copied()
    }
}

let word = Word { surface: "本", features: ["名詞", "一般"] };
assert_eq!(word.feature(1), Some("一般"));
assert_eq!(word.features(), "名詞,一般");
}

列の意味は辞書で決まります。IPADIC では、列 0 が品詞、列 6 が原形です。このクレートは、列を番号ではなく、スキーマを通して役割で読みます。

Sentence / Bunsetsu

Sentence は、形態素と、それをまとめる Bunsetsu（文節）を持ちます。文節は形態素の範囲で、次を持ちます。

  • 係り先。係る先の文節の番号で、根は None
  • 係りの種類（ArcType）。D はふつうの係り受け、P は並列、A は同格、I は不完全な並列
  • 主辞と機能語の位置と、スコア（どちらも省略できる）

Sentence::violations は、文が、解析器の仮定する木でない点を報告します。根は 1 つで最後の文節、係り先はすべて右、係りは交差しない、という木です。

ラティス形式

lattice モジュールは、cabocha -f1 の形式を読み書きします。CaboCha と J.DepP のツールがやり取りする形式です。文節の行は * で始まり、文節の番号、係り先の番号と係りの種類（根は -1）、省略できる主辞と機能語の位置、スコアが続きます。形態素の行は、表層、タブ、素性の文字列です。EOS が文の終わりです。

#![allow(unused)]
fn main() {
use lindera_dependency::Morpheme;
use lindera_dependency::lattice;

// 彼は | 本を | 読んだ。 as `cabocha -f1` writes it.
let text = "\
* 0 2D 0/1 -1.500000
彼\t名詞,代名詞,一般,*,*,*,彼,カレ,カレ
は\t助詞,係助詞,*,*,*,*,は,ハ,ワ
* 1 2D 0/1 -1.500000
本\t名詞,一般,*,*,*,*,本,ホン,ホン
を\t助詞,格助詞,一般,*,*,*,を,ヲ,ヲ
* 2 -1D 0/1 0.000000
読ん\t動詞,自立,*,*,五段・マ行,連用タ接続,読む,ヨン,ヨン
だ\t助動詞,*,*,*,特殊・タ,基本形,だ,ダ,ダ
。\t記号,句点,*,*,*,*,。,。,。
EOS
";
let sentences = lattice::parse(text)?;
let sentence = &sentences[0];
for bunsetsu in &sentence.bunsetsu {
    let surface: String = sentence.morphemes[bunsetsu.morphemes.clone()]
        .iter()
        .map(|morpheme| morpheme.surface())
        .collect();
    println!("{surface} -> {:?} ({})", bunsetsu.head, bunsetsu.arc_type);
}
assert!(sentence.violations().is_empty());

// Writing gives the text back.
let mut output = Vec::new();
lattice::write(&mut output, sentence)?;
assert_eq!(output, text.as_bytes());
}
彼は -> Some(2) (D)
本を -> Some(2) (D)
読んだ。 -> None (D)

文節の行がない文は、形態素だけの文です。トークナイザが MeCab の形式で書き出すものと同じです。スコアは、CaboCha と同じく小数 6 桁で書き出します。

Schema

Schema は、辞書について分かっていることをデータとして持ちます。どの列が品詞・活用・原形か、どの形態素が機能語か、どれが助詞か、記号をどう見分けるか、です。主辞と機能語を参照してください。

Chunker / ChunkerModel

Chunker は、素性の文字列から重みへの表と、その表の学習に使ったスキーマ、列、テンプレートで、形態素を文節に区切ります。これらは ChunkerData トレイトを通して読みます。読む先は、メモリ上の ChunkerModel（学習の結果）か、モデルファイルの区切りの部分です。文節の区切りを参照してください。

Model / ModelBuilder

Model は、辞書のモデルファイルです。所有するか借りるバイト列を、その場で読みます。辞書の名前、スキーマ、学習した部分（文節の区切りと解析器）を持ちます。Model::analyze は、文を形態素から係り受けまで解析します。ModelBuilder はファイルを書きます。モデルファイルを参照してください。

Parser / Classifier

Parser は、shift-reduce で各文節の係り先を求めます。1 回の判定の素性は、スキーマを通して作る文字列です。FeatureSet がどの群の素性を作るかを決め、Classifier が、素性の重みとその対の重みを足して点数を付けます。モデルファイルの分類器は ParserPart で、ファイルのバイト列の上で重みを読みます。ParserModel は、学習の結果の重みをメモリに持ちます。LinearClassifier は、手で作った重みを受け取ります。parser::instances は正解のある文から学習事例を作り、parser::train がそれで学習します。係り受けの解析を参照してください。

コマンド

このクレートにバイナリはありません。コマンドは lindera-cli の lindera dependency で、そのクレートの dependency feature の裏にあり、既定のビルドに入っています。lindera-cli の train feature（これも既定のビルドに入っています）を付けると、学習データを作る、学習する、評価するサブコマンドが加わります。

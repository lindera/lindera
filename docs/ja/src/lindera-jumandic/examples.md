## ユーザー辞書を使用したトークナイズ (CSV フォーマット)

```shell
% echo "東京スカイツリーの最寄り駅はとうきょうスカイツリー駅です" | lindera tokenize \
  --dict embedded://jumandic \
  --user-dict ./resources/user_dict/jumandic_simple_userdic.csv
```

## MeCab との一致

`scripts/dependency/mecab_morphemes.sh` は、同じテキストを、MeCab と mecab-jumandic（同じソースからビルドしたもの）と、`lindera tokenize` でトークナイズします。テキストは、UD Japanese-GSD と UD Japanese-PUD の 9,100 文です。

| ファイル | 区切りが同じ | 読みまでの 6 フィールドも同じ | 意味情報も同じ |
| --- | --- | --- | --- |
| GSD dev | 99.61%（505 / 507） | 90.93%（461 / 507） | 2.96%（15 / 507） |
| GSD test | 99.63%（541 / 543） | 93.74%（509 / 543） | 4.05%（22 / 543） |
| PUD | 100%（1,000 / 1,000） | 91.30%（913 / 1,000） | 0%（0 / 1,000） |
| GSD train | 99.79%（7,035 / 7,050） | 90.30%（6,366 / 7,050） | 2.81%（198 / 7,050） |

**区切り**が違うのは 19 文です。

- 17 文は、数字の間の `・`（`66・0`）です。mecab-jumandic は `・` を数字の文字種にしていて、MeCab は `66・0` を 1 つの数として読みます。Lindera は、区切り文字（既定は `・`）をまたぐ未知語を作りません。`lindera tokenize --disable-break-characters` を付けると、この 17 文は同じになり、区切りが同じ文は 9,100 文のうち 9,098 文になります。
- 1 文は、28 文字のカタカナの連なりです。MeCab はこれを 1 つの未知語にしません（1 文字にまとめるのは、続く 24 文字までです。`max-grouping-size`）。Lindera は 1 語にします。
- 1 文は、記号の連なり `%、「` です。MeCab は 3 文字を 1 つの未知語にし、Lindera は `%、` と括弧に分けます。

**フィールド**が違うのは、ソースに、同じ表層が同じコスト・同じ文脈 ID で 2 つあるところです。このとき、2 つの解析は同じコストになり、Lindera と MeCab は同じほうを採りません。

- **読み**は、6%〜10% の文で違います。一 は、MeCab では ひと、Lindera では いち になり、国 は こく と くに になります。
- **意味情報**は、ほぼすべての文で違います。は のような助詞は、`Postp.csv` に `*`、`Rengo.csv` に `連語` であり、MeCab は `連語` を、Lindera は `*` を出します。

語の表層、品詞、活用、原形は、これで変わりません。
